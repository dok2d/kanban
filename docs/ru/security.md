# Безопасность

## Хардинг контейнера

Контейнер запускается с максимальными ограничениями:

| Мера                    | Описание                                          |
|-------------------------|---------------------------------------------------|
| **Non-root**            | Процесс работает от пользователя `kanban`         |
| **Read-only FS**        | Корневая ФС смонтирована только для чтения        |
| **CAP_DROP ALL**        | Все Linux capabilities отключены                   |
| **no-new-privileges**   | Повышение привилегий заблокировано                 |
| **Лимиты ресурсов**     | 256 МБ RAM, 0.5 CPU                               |
| **Сеть**               | Слушает только 127.0.0.1, наружу через nginx       |
| **Health check**        | Встроенная проверка здоровья контейнера            |

## Аутентификация

- **PBKDF2-HMAC-SHA256** — 100 000 итераций, 32-байтная соль
- Сессии: случайные 64-символьные токены, срок 90 дней
- HttpOnly cookies — защита от кражи через XSS
- Автоматическая очистка просроченных сессий

## Защита от атак

### SQL Injection

Все запросы к БД используют подготовленные выражения (prepared statements).

### XSS

- Заголовок Content-Security-Policy (CSP)
- HTML-экранирование пользовательского ввода
- HttpOnly cookies

### Загрузка файлов

- Лимит размера: 50 МБ
- Проверка MIME-типа
- Блокировка опасных расширений: `.exe`, `.bat`, `.js`, `.html`, `.svg` и др.

## nginx

Конфигурация nginx включает:

- TLS 1.2 / 1.3 с современными шифрами
- HSTS (HTTP Strict Transport Security)
- X-Frame-Options: DENY
- X-Content-Type-Options: nosniff
- Referrer-Policy: strict-origin-when-cross-origin
- Зона rate limiting для защиты от брутфорса
- Лимит тела запроса: 2 МБ

## Рекомендации

- Используйте TLS в production (самоподписанный или Let's Encrypt)
- Регулярно делайте [бэкапы](backup.md)
- Ограничьте доступ к серверу по сети (firewall)
- Используйте сложные пароли для администратора
- Рассмотрите LDAP/OIDC для корпоративного использования
