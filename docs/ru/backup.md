# Резервное копирование

## Бэкап базы данных

### Создание бэкапа

```bash
./kanban.sh backup
```

Копия сохраняется в директорию `./backups/` с временной меткой в имени файла.

### Восстановление из бэкапа

```bash
./kanban.sh restore
```

Команда предложит выбрать файл из `./backups/`.

## Экспорт и импорт (JSON)

### Экспорт

Администратор может экспортировать всю доску в JSON через интерфейс или API:

```
GET /api/export
```

Экспорт включает:

- Колонки и их порядок
- Задачи с описаниями, приоритетами, дедлайнами
- Спринты, эпики, теги
- Комментарии
- Пользователей (опционально — с хешами паролей)
- Настройки
- Файлы и изображения (опционально)

### Импорт

```
POST /api/import
```

Импорт восстанавливает доску из ранее экспортированного JSON-файла. Все существующие данные будут заменены.

При восстановлении из бэкапа (через API или интерфейс) система автоматически создаёт страховочную копию текущего состояния — файл `pre-restore-{timestamp}.json`. Это позволяет откатиться, если восстановление прошло неудачно.

## Автоматические бэкапы через Telegram

Если настроен Telegram-бот, сервер автоматически отправляет ежедневный бэкап всем администраторам с привязанным Telegram. Бэкап отправляется в **18:00** по часовому поясу администратора (настройка `admin_timezone`, по умолчанию UTC).

Особенности:
- Бэкап отправляется как JSON-файл (`kanban-backup-YYYY-MM-DD.json`) через Telegram-бота
- Если данные не изменились с последнего бэкапа, отправка пропускается
- Перед каждым бэкапом автоматически очищаются осиротевшие файлы и изображения
- Для работы автобэкапа необходимо: настроенный Telegram-бот и хотя бы один администратор с привязанным Telegram

## Очистка осиротевших файлов

Перед каждым бэкапом (ручным и автоматическим) система автоматически удаляет загруженные файлы и изображения, которые больше не привязаны ни к одной задаче или комментарию.

## Рекомендации

- Делайте бэкапы регулярно, особенно перед обновлениями
- Храните копии бэкапов за пределами сервера
- Экспорт в JSON удобен для миграции между серверами
- SQLite использует WAL-режим — бэкап безопасен при работающем сервере
